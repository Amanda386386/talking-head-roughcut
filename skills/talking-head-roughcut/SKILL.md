# 口播粗剪（talking-head rough cut）

单机位口播 + 口播稿 → 对齐校准 → 去重录/卡壳/长气口 → 切点换景别 → 原分辨率原码率成片。
只做粗剪：不加字幕、花字、调色、BGM、音效；变速只做整体倍速（`--speed`），不做局部变速/卡点。

## 一、五条铁律（每次都必须满足）

| 规则 | 程序怎么落实 | 交付前怎么自查 |
|---|---|---|
| 同一段台词连录多次，只留最后一次；前面说一半又重说的，**前面那半句整段删掉** | 逐句在整条音轨里找所有出现位置，选覆盖台词最多、时间最靠后的那条链；句首说了半句停住再重来（如「是不是就 / 是不是就能…」「不知道该注 / 不知道该注册成哪种类型」）用 20ms 能量包络找停顿，从重来处起剪；句尾若把后面重复的半句「吸」进来（多出来的尾段与下一句 2-gram 重合 ≥50%），尾巴收回句尾词，重复段整段删 | 看 `粗剪报告.md` 第二节「重录」；同一句在 `剪点表.csv` 里只应出现一次；**通听一遍，不能听到半句重复**（如「那海南这边的园区地址费用呢 → 海南这边园区地址费用呢」这种要删掉前面那句） |
| 卡壳、超过约 0.5s 的长气口剪掉，**其中任何 ≥3s 的静默必须剪掉**；正常气口保留 | 词间静音 > `--gap-cut`(0.5s) 才裁：断句处留 0.12s，句内长气口留 0.10s；≤0.5s 的停顿原样保留；孤立「嗯/呃/额」和同词重复（如"这个这个"）整段挖掉 | 报告第三节的气口条数；剪点表里不应出现半句话；**3 秒以上的空等一处都不能有** |
| 句尾语气词和模糊限定词必须留全 | 句尾词属于 `TAIL_TOKENS`（呢/啊/吧/啦/嘛/呀/了/的/左右/上下/大概/差不多/之类）时，按能量包络再往后延最多 0.5s，宁可多留半拍 | **「1000-2000左右」不能变成确切的「1000-2000」**；句尾的「呢/啊/了」不能缺半拍 |
| 切气口时画面换景别，且不能剪到字 | 每段按 `--zoom-cycle`（默认 1.0,1.09）交替缩放，切点一律对齐帧后再检查是否压到词，压到就向外挪一帧 | 抽 2–3 个切点看前后 0.3s：画面景别变了，但人声没有半个字被切 |
| 清掉拖节奏的长空档，保留断句/转场/强调的停顿 | 句间长静音压到 0.12s，句内长静音压到 0.10s；正常换气不动 | 通看一遍，语句之间不"赶"，也没有明显空等 |

## 二、前置检查

1. **素材**：单个视频文件（.mov/.mp4 均可），最好一条长录。
2. **口播稿**：.docx / .txt / .md。docx 里常带封面、标题、配文、话题标签，脚本默认只取**最长正文段**（长度 ≥ 最长段 70% 的段落）。稿子分多段时用 `--paragraph all`；取错段用 `--paragraph N`。
3. **环境**：`scripts/environment.json` 里填 `ffmpeg` / `ffprobe` / `model` / `python`，或设 `KOU_BO_FFMPEG`、`KOU_BO_FFPROBE`、`KOU_BO_MODEL`。本机已配好：ffmpeg 9.0.2 + faster-whisper large-v3（int8/CPU）+ 对应 Python 3.12 虚拟环境。

## 三、标准流程（三步，不要跳）

### 第 1 步：出方案（不渲染）

```powershell
& "<environment.json 里的 python>" -X utf8 "<skill 目录>\scripts\roughcut.py" `
  --video "<素材.MOV>" --script "<口播稿.docx>" --dry-run
```

产出 `<素材名>_粗剪\`：`plan.json`、`剪点表.csv`、`粗剪报告.md`。
先跑 dry-run 是因为识别 + 对齐要 1–3 分钟，而返修参数只重算方案，不用重新识别。

### 第 2 步：校准（必须人工过一遍表）

打开 `粗剪报告.md` 的「台词匹配校准」表，逐条确认：

- **采用率**：低于 90% 先别渲染。脚本在对齐率 < 75% 时会直接报错。
- **识别结果列**如果和台词差太远，说明稿子取错段（换 `--paragraph`）或素材不是这条稿。
- **重录**：确认丢弃的是更早那几次，保留的是最后一次。
- **需要人工确认**里的句子：用 `--overrides` 把这句话钉到素材里的真实时间段再跑。

```json
{ "5": [29.6, 36.7], "12": [74.0, 75.6] }
```

键是台词序号（从 1 开始），值是素材入点/出点（秒）。

### 第 3 步：渲染 + 校验

```powershell
& "<python>" -X utf8 "<skill 目录>\scripts\roughcut.py" --from-plan "<素材名>_粗剪\plan.json"
```

渲染默认两遍编码（ABR 对准原码率），单遍会低 5–8%。渲染后脚本会打印 ffprobe 实测值。必须核对：

- 分辨率、帧率 = 原素材；视频码率 ≈ 原素材（ABR 目标 = 原视频码率）。
- 时长 = Σ 每段时长；比原片短多少要能对上报告里的删除量。
- 音频 44.1kHz / 双声道 / 原码率，原声、不变调。

## 四、参数

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--gap-cut` | 0.5 | 语速慢、气口多 → 0.45；想更稳 → 0.6 |
| `--keep-sentence` | 0.12 | 断句太赶 → 0.2–0.3；还想更紧 → 0.08 |
| `--keep-inner` | 0.10 | 句内长停顿留多少 |
| `--zoom-cycle` | 1.0,1.09 | 景别变化太跳 → 1.0,1.05；想更明显 → 1.0,1.12 |
| `--no-zoom` | 关 | 用户明确要纯硬切时 |
| `--min-cov` / `--min-sim` | 0.8 / 0.72 | 口音重、识别错字多 → 0.75 / 0.68 |
| `--paragraph` | auto | docx 正文段选错时用 `all` 或序号 |
| `--calibrate` | 关 | 对齐率低时开：换一种解码方式整段再识别一遍，逐句取更优；耗时约翻倍 |
| `--speed` | 1.0 | 整体倍速（视频 setpts + 音频 atempo，不变调）；本机作者语速偏慢，常用 **1.05** |
| `--single-pass` | 关（默认两遍） | 想快一倍、可接受码率低 5–8% 时用 |
| `--force-asr` | 关 | 换了稿子或改了提示后强制重新识别 |

## 五、输出

```
<素材名>_粗剪\
  <素材名>_粗剪.mp4   成片（原分辨率/帧率/码率）
  剪点表.csv          每段：素材入点/出点/时长/景别/对应台词/备注
  粗剪报告.md         对齐校准表、重录记录、气口统计、待确认项
  plan.json           可复现的剪辑方案（--from-plan 直接渲染）
  asr.json            识别缓存（词级时间戳）
  audio16k.wav        识别用音轨
```

## 六、故障排查

| 现象 | 原因 / 处理 |
|---|---|
| `TypeError: open() got an unexpected keyword argument 'metadata_errors'` | PyAV 与 faster-whisper 版本不匹配。脚本已改为传 numpy 数组，不要走文件路径 |
| `找不到 ffmpeg/模型` | 改 `scripts/environment.json`，或设 `KOU_BO_*` 环境变量 |
| 对齐率低、识别结果开头出现后文内容 | 提示词被塞了长稿导致 Whisper 幻觉。initial_prompt 只用短通用提示，不要拼口播稿 |
| `[sandbox: file access denied]` 写不进目录 | 该目录 ACL 缺当前用户写权限；用 DSH 的 `diagnose-windows-sandbox-acl` 修，不要手工改权限 |
| 渲染慢 | 段数多时把 `--preset` 调到 `veryfast`；分辨率不变 |
| 切点有半个字 | 说明 ASR 词边界偏了；把该句 `--overrides` 指准，或把 `--gap-cut` 调大 0.05 |
| 句尾发闷、像少半个字 | 词尾时间偏早：脚本已用能量包络把边界推到静音边缘；仍明显就把 `--keep-sentence` 调大 0.05 |
| **听到半句重复**（「那海南这边的园区地址费用呢 / 海南这边园区地址费用呢」） | 句尾吸附把后面重复的半句吞进了前一句。已由 `trim_duplicate_tails` 挡住：多出来的尾段与下一句 2-gram 重合 ≥50% 就收回句尾、重复段整段删。仍出现就把该句 `--overrides` 指准，别靠调参数 |
| **「左右 / 上下 / 呢 / 啊」被切掉**，数字变确切 | 句尾模糊限定词保护 `extend_tail`：按能量包络再延最多 0.5s。**不要用加字幕补**，也不要把这类词当废字删 |
| **3 秒以上的空等还在** | 说明那段静默被算进了前一句的尾巴（`snap_span` 吸附过头）；看 `剪点表.csv` 那一段的时长，用 `--overrides` 收窄，或确认 `--gap-cut` 没被调大 |
| 起句口误在句首 1.2s 之外（如「不知道该注…」） | `trim_stammer_at` 窗口已放宽到 2.6s：找被拉长的短字（≤2 字、却占了 ≥0.9s）里的 ≥0.3s 静音，从静音结束处起剪 |
| `ffmpeg ... Permission denied` 写不进输出目录 | Windows 沙箱只授权工作区根目录。先把 `--out-dir` 指到工作区根目录下的路径，跑完再拷回素材目录 |
| 识别开头整段变成「请不吝点赞 订阅 转发」 | Whisper 在片头静音处幻觉。用 `vad_filter=True` 重转一遍再写回 `asr.json` 缓存（脚本读缓存，不重跑 ASR） |

## 七、实现要点（改代码前先读）

- **识别**：faster-whisper large-v3，词级时间戳，`vad_filter=False`（停顿自己算）。`initial_prompt` 只放短通用提示，**不要把口播稿塞进去**——会诱使模型在开头幻觉出后文。
- **对齐**：剧本按 16 字左右的逗号/句号切单元；每句用 1/2/3-gram 倒排找候选窗口，再用 Smith-Waterman 局部对齐算覆盖率和起止时间。
- **重录**：每句可有多条候选，动态规划选一条时间递增、覆盖最多、同覆盖率下时间最靠后的链——即"只保留最后一次"。
- **切点**：先用 20ms 能量 VAD 把语音段切准，句子首尾吸附到语音段边缘；≤0.5s 的停顿直接保留不切，只有 >0.5s 的长停顿才切，切点落在静音里。音频与视频用同一时间，避免累积不同步。
- **尾音保护**：Whisper 词尾常偏早（「了」标 7.02s，实际说到 7.19s，「楚」被当成独立 0.12s 语音段），吸附时把 <0.12s 的短碎片并回前一段，尾音（呢/的/楚/啊）不会被切掉。
- **句尾限幅**：`snap_span` 起点最多回退 0.30s、终点按语音段末尾吸附；不加限幅会把紧贴的重复句整段吸进前一句。
- **重复尾段**：`trim_duplicate_tails` 检查句尾多出来的语音与下一句的 2-gram 重合率，≥0.5 判为「重复半句」，尾巴收回句尾词，重复段整段删；只重合不到一半的是正常尾音（「讲清楚」），保住。
- **模糊限定词**：`extend_tail` 对 `TAIL_TOKENS` 收尾的句子按能量包络再延最多 0.5s（「左右」常被切成「左」「右」两段语音，要贴到后一段的末尾）。
- **严格对照文案**：长停顿里多出来的语音（口误、临时衔接词，如「那以后呢」）整段删掉，只保留口播稿里的句子；短停顿（≤0.5s）里的语气词照旧保留。
- **气口**：>0.5s 才裁，句间留 0.12s、句内留 0.10s，裁掉的部分从时间轴上整段删除（不是把静音留在段内）。
- **起句卡壳重来**：ASR 会把「是不是就（停）+ 是不是就能…」并成一个 1.48s 的「能」，文本上看不出重复；用 RMS 包络在段首 2.6s 内找被拉长的短字，定位其中 ≥0.3s 的静音，把段首到静音结束剪掉。
- **切景**：每段交替 1.0/1.09 缩放并居中裁切回原尺寸，切点换景别遮掉单机位硬切的跳帧。
- **编码**：两遍 ABR，目标 = 原视频码率 / 原音频码率，分辨率、帧率、像素格式、色彩标记全部沿用原素材。
- **倍速**：`--speed` 用视频 `setpts=PTS/倍速` + 音频 `atempo`，不变调；成片时长 = 剪后时长 / 倍速。

## 八、不要做

- 不要给粗剪加花字、转场特效、调色、局部变速、BGM、音效——那是精剪，另起流程。
- 字幕只在用户明确要求时加，用 `scripts/make_subtitles.py`，遵循下面第九节的《字幕规范》；不要用剪映/其他工具另做一套断行规则。
- 不要改分辨率、帧率、像素格式；不要用 TTS 重配或替换原声。
- 不要在没看 `剪点表.csv` 的情况下直接交付；重录句、长空档、待确认句必须逐条过。
- 不要把 `plan.json` 里没覆盖的台词段落当成"本来就没有"——先查对齐率。
- 不要把句尾语气词、「左右」这类模糊限定词当废字剪掉：那是说话人的留余地，剪了语义就变了。
- 不要用字幕或补画面去掩盖粗剪阶段的尾音缺失、半句重复；回到方案里改切点。

## 九、字幕（可选，按《字幕规范》）

粗剪成片默认不带字幕。用户说要字幕时，用 `scripts/make_subtitles.py` 直接从 `plan.json` 生成并压制，不要手工排版。

### 规范（必须遵守）

1. 结合上下文，不做全局删字；「金额」的「额」、语义性的「那/了/的」和必要承接词保留。
2. 不显示句读标点（，。？！：；、""''（）…—）；**顿号换成一个半角空格**，保留并列词分隔；其余标点用换行表达停顿。
3. 数值、型号、英文内部的有效符号和空格保留：20%、3.5、dream-album、Step Studio。
4. 按意思和口播停顿断句：一条一个完整意群，问句与回答分开；一行约 8–16 汉字，不拆词、不拆数字与单位。
5. 清字幕 ≠ 剪声音：不改口播和画面；删语气词后仍用原词对应时间，不能按删字后的索引错位。
6. 每条字幕延续到下一条开始，最后一条撑到该句结束——**不吃尾音**（句尾「呢/啊/了」必须覆盖到）。

### 命令

```powershell
# 只生成 ASS（不改视频）
python scripts/make_subtitles.py --plan <粗剪目录>/plan.json --out <粗剪目录>/subtitles.ass

# 生成并压制成片（1080x1920，字号 62，底部留 95）
python scripts/make_subtitles.py --plan <粗剪目录>/plan.json --out <粗剪目录>/subtitles.ass `
    --burn <粗剪目录>/待剪视频_粗剪.mp4 --out-video <粗剪目录>/待剪视频_字幕版.mp4
```

- 横版素材加 `--width 1920 --height 1080`，字号和底部留白按画面调。
- 句尾被切（例如「呢」听不到）属于粗剪阶段的尾音问题：先用 `--keep-sentence` 调大 0.05 重出粗剪，再加字幕；不要靠延长字幕掩盖。

### 用户侧一句话

> 用 talking-head-roughcut 粗剪这条视频，文案在〈路径〉，剪完按字幕规范加字幕。

技能会依次做：粗剪方案 → 人工确认剪点表 → 渲染粗剪 → `make_subtitles.py` 生成字幕并压制。
